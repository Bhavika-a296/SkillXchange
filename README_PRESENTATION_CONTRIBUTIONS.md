## Presenter 1 - Contribution Part A (6 Functionalities)

### 1) User Authentication and Profile Management
What it does:
- Lets users register, login, and maintain profiles.
- Stores bio, profile details, and personal skill data.

How we achieved it:
- Built token-based authentication APIs.
- Added profile models and serializers.
- Integrated protected routes in frontend.

What we used:
- Django REST Framework Token Authentication
- Django models and serializers
- React context for auth state
- Axios for API calls

What to say:
- "I implemented secure login and registration flow with token auth."
- "I connected backend auth endpoints with protected frontend pages."
- "This became the foundation for all other personalized features."

### 2) AI-Powered Skill Matching
What it does:
- Matches learners with relevant teachers using semantic similarity.
- Supports near-meaning matches, not only exact keyword matching.

How we achieved it:
- Converted skills and search terms into embeddings.
- Calculated cosine similarity scores.
- Returned best ranked matches above threshold.

What we used:
- Sentence Transformers (paraphrase-MiniLM-L6-v2)
- Scikit-learn cosine similarity
- Django utility layer for safe model usage

What to say:
- "I used embedding-based matching so similar skill terms can still connect users."
- "This improved the quality of search and recommendations."
- "The ranking is generated by cosine similarity scores."

### 3) Resume Upload and Skill Extraction
What it does:
- Allows users to upload resumes.
- Extracts skill signals from document text to enrich profile.

How we achieved it:
- Added resume upload endpoint and file handling.
- Parsed text from PDF resumes.
- Matched extracted text to skill dataset and updated user skills.

What we used:
- Django file upload handling
- PyPDF2 for PDF text parsing
- Skills keyword mapping and backend processing

What to say:
- "I automated skill onboarding through resume parsing."
- "This reduces manual profile setup effort for users."
- "Extracted skills can be used directly in matching and discovery."

### 4) User Discovery and Connection Workflow
What it does:
- Lets users explore others, discover skills, and create connections.
- Supports relationship statuses like pending and connected.

How we achieved it:
- Built search and list APIs for exploration.
- Added connection model and status transitions.
- Connected actions in UI for sending and handling requests.

What we used:
- Django models for connections
- REST endpoints for request/accept/reject flow
- React page components for Explore experience

What to say:
- "I handled the discover-to-connect journey so users can build learning networks."
- "Connection states are tracked and shown clearly in UI."
- "This is the social layer before starting any learning session."

### 5) Real-Time Messaging with File Sharing
What it does:
- Provides instant chat between users.
- Supports sending text and shared files.

How we achieved it:
- Added messaging APIs for history and persistence.
- Integrated real-time pub/sub channels for live delivery.
- Added unread tracking and chat file storage.

What we used:
- Ably for real-time communication
- Django APIs for message persistence
- React messaging page and realtime context

What to say:
- "I implemented real-time communication using Ably channels."
- "Messages are instant on UI and also safely stored in backend."
- "This enables active coordination between learner and teacher."

### 6) Notification System
What it does:
- Notifies users about key events like requests, approvals, badges, and messages.
- Helps users stay updated without manually checking every page.

How we achieved it:
- Created notification records during key backend actions.
- Added unread/read handling.
- Displayed notifications through popup and notification pages.

What we used:
- Django notification model and viewset
- Frontend notification manager components
- Realtime + API polling strategy

What to say:
- "I created a centralized event notification system across modules."
- "Users receive timely updates for workflow continuity."
- "This improves engagement and user retention."

## Presenter 2 - Contribution Part B (6 Functionalities)

### 1) Learning Request and Approval Flow
What it does:
- Converts direct join into teacher-approved workflow.
- Session starts only after teacher accepts the request.

How we achieved it:
- Added pending and rejected learning statuses.
- Created APIs for request listing, accept, and reject.
- Updated UI to show pending requests and action buttons.

What we used:
- Django views for workflow control
- LearningSession status state machine logic
- React LearningRequests component and route

What to say:
- "I implemented the approval gate so session creation is controlled and fair."
- "Points are not deducted at request time, only after approval."
- "This improves trust and prevents accidental session starts."

### 2) Points Economy and Transaction Tracking
What it does:
- Creates a reward loop: spend points to learn, earn points by teaching.
- Maintains wallet balance and full transaction history.

How we achieved it:
- Added configurable point rules table.
- Added user point balance and transaction models.
- Enforced point checks and atomic updates in APIs.

What we used:
- PointConfiguration, UserPoints, PointTransaction models
- Django ORM transactions for consistency
- Backend endpoints for points and statements

What to say:
- "I built a configurable point economy instead of hardcoding values."
- "Every point change is logged for transparency and debugging."
- "This gamifies participation and keeps the system sustainable."

### 3) Learning Session Lifecycle and Progress Tracking
What it does:
- Tracks active sessions from start to completion.
- Shows progress percent and remaining days.

How we achieved it:
- Designed session model with start, end, and status fields.
- Added derived properties for progress and day calculations.
- Built frontend cards to display real-time progress state.

What we used:
- Django LearningSession model
- Date-time based progress computation
- React Learning page and session card UI

What to say:
- "I created end-to-end lifecycle tracking for each learning session."
- "Progress is computed dynamically from time and session duration."
- "Users can clearly see what is in-progress vs completed."

### 4) Mutual Rating and Feedback
What it does:
- Allows both learner and teacher to rate each other after completion.
- Supports stars and written feedback.

How we achieved it:
- Added rating model linked to sessions.
- Enforced one rating per user per session.
- Built submit and fetch APIs with validation checks.

What we used:
- SkillRating model with constraints
- Rating endpoints and serializer validation
- React rating component with interactive stars

What to say:
- "I implemented trust signals through post-session ratings."
- "Ratings are only allowed after completion, improving quality."
- "Mutual feedback improves accountability on both sides."

### 5) Badge Achievement System
What it does:
- Awards milestone badges based on skills learned and taught.
- Motivates consistent platform usage.

How we achieved it:
- Counted unique completed skills as learner and teacher.
- Defined milestone thresholds and badge categories.
- Triggered badge checks after session completion.

What we used:
- Backend milestone logic in learning flow
- Badge-aware profile and UI sections
- Notification hooks for new badge events

What to say:
- "I added milestone-based achievements to increase motivation."
- "Badges are automatic and based on verified completed sessions."
- "This introduces gamification and long-term engagement."

### 6) Teacher Skill Verification Quiz (AI Generated)
What it does:
- Verifies teacher expertise in specific skills.
- Displays verified badges to improve learner confidence.

How we achieved it:
- Generated quiz questions using local AI model workflow.
- Added quiz attempts, score evaluation, and pass threshold logic.
- Exposed public verification view on teacher profile.

What we used:
- Ollama local AI integration
- Quiz models: SkillQuiz, TeacherQuizAttempt, TeacherVerification
- Backend quiz endpoints for generate/get/submit flow

What to say:
- "I implemented AI-based skill verification to increase platform credibility."
- "Teachers earn verified status based on quiz performance."
- "Using local AI keeps cost low and deployment flexible."
